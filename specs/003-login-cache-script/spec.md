# Feature Specification: 测试登录凭证流程迁移至独立脚本

**Feature Branch**: `003-login-cache-script`

**Created**: 2026-09-03

**Status**: Draft

**Input**: User description: "把test的命令登录凭证流程迁移至scripts/login_and_cahce.py文件"

## Clarifications

### Session 2026-09-03

- Q: 独立脚本在不带任何参数运行时应该做什么？ → A: 输出用法提示并退出，必须显式指定登录方式（qrcode / phone）才进入交互。
- Q: 脚本登录成功后，凭据应立即写入缓存，还是先联网校验通过后再写入？ → A: 立即写入缓存，不做额外联网校验；有效性校验留给测试运行时按需进行（与现有 --login 行为一致）。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 独立脚本登录并缓存测试凭据 (Priority: P1)

开发者在不启动测试的情况下，直接运行登录脚本并选择扫码或短信方式，通过终端交互完成 B 站登录。登录成功后凭据自动写入既有的系统临时目录缓存文件；此后运行需登录的测试时零交互自动复用该缓存。

**Why this priority**: 这是本次迁移的核心交付——获取测试凭据的能力从测试命令中独立出来，开发者可以预取凭据、为其他开发场景（如运行单个验收脚本）提供登录入口，而不必把登录绑死在 pytest 上。

**Independent Test**: 运行脚本完成一次扫码登录并确认缓存文件生成；随后运行任意需登录的测试用例，确认零交互通过且提示使用了缓存凭据。

**Acceptance Scenarios**:

1. **Given** 本机无有效凭据来源，**When** 运行脚本选择扫码登录并完成扫码确认，**Then** 终端提示登录成功且凭据写入 TEMP 缓存文件，全程不输出任何凭据字段值。
2. **Given** 已通过脚本登录并缓存凭据，**When** 直接运行测试命令（不带 `--login`），**Then** 需登录用例自动使用缓存凭据（有效性校验通过）且无任何登录交互。
3. **Given** 运行脚本选择短信登录，**When** 依次完成地区码 / 手机号输入、浏览器滑块验证、验证码输入，**Then** 登录成功且凭据写入缓存文件；触发风控二次验证时同样可完整走完并写入。

---

### User Story 2 - 测试命令登录入口行为不回归 (Priority: P2)

现有 `--login qrcode|phone` 测试工作流在迁移后保持可用，交互过程、成功 / 中止行为与提示语义和迁移前一致，既有文档描述的使用方式继续成立。

**Why this priority**: 迁移不得破坏既有开发者的使用习惯与文档承诺，这是兼容性底线；但相对 P1 属于"保持现状"而非新增价值。

**Independent Test**: 分别以扫码与短信方式触发测试命令的临时登录，对照迁移前行为核对：成功写缓存、中止不写缓存、凭据回退链不变。

**Acceptance Scenarios**:

1. **Given** 迁移完成，**When** 运行测试命令并附带扫码登录选项、完成扫码，**Then** 行为与迁移前一致：凭据写入缓存、提示语义一致。
2. **Given** 登录过程中用户中断或二维码连续 3 次超时，**When** 中止发生，**Then** 不写入缓存文件、既有缓存不受影响，需登录用例按既有回退链处理。

---

### User Story 3 - 两种入口共享统一的缓存与刷新逻辑 (Priority: P3)

独立脚本与测试运行对缓存文件的全部处理（读取、格式校验、联网有效性校验、过期刷新、回写、损坏清理）由同一套实现提供，行为一致、契约单一，杜绝双实现漂移。

**Why this priority**: 属于质量属性（可维护性），不影响主流程可用性，但缺失会导致两处行为逐渐分叉。

**Independent Test**: 分别从脚本入口与测试入口触发同一缓存场景（如过期刷新、缺少刷新材料），确认处理结果与提示语义一致。

**Acceptance Scenarios**:

1. **Given** 缓存中的凭据已过期且含刷新材料，**When** 任一入口触发刷新，**Then** 凭据刷新成功并回写缓存文件，两入口行为一致。
2. **Given** 缓存凭据已过期且缺少刷新材料，**When** 任一入口处理，**Then** 删除缓存文件并回退到环境变量 / cookie 来源，两入口行为一致。

### Edge Cases

- 登录中止（用户中断 / 二维码连续 3 次超时 / 流程失败 / 非交互终端输入流关闭）时，MUST NOT 写入或破坏既有缓存文件，并给出不含凭据值的中止原因。
- 终端无法渲染二维码字符时，回退为提示系统临时目录下的二维码图片路径。
- 短信流程触发风控二次验证（需再次滑块验证 + 二次短信验证码）时，流程可完整走完。
- 缓存文件不存在时给出提示；内容不合法（corrupt）时按既有语义清理并回退，不阻断流程。
- 缓存有效性校验遇网络异常时，保留缓存文件并给出可读提示（测试侧跳过需登录用例，不做破坏性清理）。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 项目 MUST 提供独立可运行的登录脚本 `scripts/login_and_cache.py`，支持扫码（qrcode）与短信验证码（phone）两种交互式登录方式；登录方式 MUST 显式指定，未指定时脚本 MUST 输出用法提示并退出（不进入任何交互）。
- **FR-002**: 脚本登录成功后 MUST 立即将凭据写入与现有测试临时登录相同的系统 TEMP 缓存文件（名称与 base64(UTF-8 JSON) 格式契约均不变，沿用 specs/001 契约），写入前不做额外联网校验。
- **FR-003**: 测试命令的 `--login` 选项 MUST 保持可用且行为兼容：登录成功写缓存、中止不写缓存、凭据回退链（新登录 > 缓存 > 环境变量 > cookie 文件）不变，其登录实现由迁移后的脚本模块提供。
- **FR-004**: 缓存文件的读取、合法性校验、联网有效性校验、过期刷新与回写逻辑 MUST 由脚本模块统一提供，独立脚本与测试装配共用同一实现。
- **FR-005**: 登录中止或失败时 MUST NOT 写入或破坏既有缓存文件。
- **FR-006**: 所有提示、错误与日志输出 MUST NOT 包含任何凭据字段值（只允许字段名与状态描述）。
- **FR-007**: 迁移完成后，测试配置文件 MUST 不再包含登录流程的实现（二维码生成与轮询、短信与极验交互、登录用事件循环管理），仅保留凭据装配、回退链与测试专属设置（限速、超时）。
- **FR-008**: 独立脚本 MUST 在非交互环境（stdin 不可用）下优雅中止：输出明确原因并正常退出，不产生半成品状态。

### Key Entities *(include if feature involves data)*

- **登录凭据字段集合**: sessdata / bili_jct / dedeuserid（必需）与 ac_time_value / buvid3 / buvid4（可选），来源于登录成功结果。
- **凭据缓存文件**: 系统临时目录下固定名称的 base64(UTF-8 JSON) 文件；读取三态（缺失 / 内容不合法 / 合法）；同机后一次登录覆盖前一次。
- **凭据来源回退链**: 临时登录新凭据 > TEMP 缓存 > BILI_* 环境变量 > .bilibili.cookie 文件。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 开发者仅通过运行脚本并完成扫码 / 短信交互即可获得缓存凭据，除登录交互外无任何额外手动步骤；随后的测试运行零交互复用该凭据。
- **SC-002**: 迁移后测试命令临时登录的可观察行为与迁移前一致（缓存写入语义、中止语义、回退链、提示语义），既有使用方式无需改变。
- **SC-003**: 同一缓存场景（过期刷新、缺少刷新材料时清理等）从任一入口触发，处理结果与提示语义一致。
- **SC-004**: 迁移后可按代码位置审计验证：登录流程实现集中位于 `scripts/login_and_cache.py`，测试配置文件中不再存在。
- **SC-005**: 迁移后离线测试与项目质量门禁全绿通过。

## Assumptions

- 用户输入中的文件名 `login_and_cahce.py` 为笔误，按正确拼写 `scripts/login_and_cache.py` 实施。
- "迁移"指实现位置变更并使脚本独立可运行，而非删除测试命令的登录能力；保留 `--login` 入口并保持行为兼容，移除该入口属破坏性变更，不在本特性范围内。
- 缓存文件路径、名称与格式契约完全沿用 specs/001-pytest-temp-login 契约，不做任何变更。
- 脚本面向开发者本机交互使用，不属于库的公开 API，不进入 `bilibili_api/` 包与文档自动生成范围。
- 登录方式取值与现有 `--login` 一致（qrcode / phone）。
- 现有 `scripts/qrcode_login.py`（002 规格的真机验收脚本，不落缓存）保持原样，不并入本特性。
- 缓存文件的查看 / 手动清除等管理子命令不在本特性范围内。
