# Feature Specification: 移除 CurlCFFI 客户端适配

**Feature Branch**: `009-remove-curlcffi-client`

**Created**: 2026-10-11

**Status**: Draft

**Input**: User description: "取消适配CurlCFFI客户端"

**背景**: 本库支持多请求客户端（三种实现按优先级自动选择），其中 CurlCFFI 适配目前处于自动选择链首位。CurlCFFI 是二进制依赖（安装体积大、平台 wheel 覆盖与 API 兼容成本高，历史上历经多个大版本变动），继续维护该适配的负担与收益不成比例。本特性将 CurlCFFI 从库的内置适配中整体移除，使自动选择回落到其余客户端，并同步清理依赖声明、测试、面向用户的文档与治理文本中的相关内容。移除的是"内置适配"，不禁止用户以自定义客户端机制注册同名第三方实现。

## Clarifications

### Session 2026-10-11

- Q: CurlCFFI 适配是立即彻底移除，还是先保留一个版本作废弃过渡？ → A: 立即彻底移除（不设废弃过渡期；以 BREAKING CHANGE 标注 + 变更记录告知下游）。
- Q: 用户代码直接导入已移除的 CurlCFFI 适配类时，应当干净移除（标准导入报错），还是保留一个抛出迁移指引的报错桩？ → A: 干净移除——适配类与模块一并删除，导入失败为标准导入错误，迁移指引由文档与变更记录承载，不留报错桩。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 未显式选择客户端的用户无感继续使用 (Priority: P1)

一个下游开发者在本库仅适配剩余客户端的版本上照常使用库的全部功能：库在运行时从剩余可用客户端中按既有优先级自动选择一个发起请求，反爬参数注入、登录态传递、WebSocket（直播弹幕等）与文件下载等能力均不受影响。此前已同时安装多个客户端库的用户在升级后自动改用剩余优先级链中的首个可用客户端；仅安装其余客户端之一的用户行为完全不变。

**Why this priority**: 这是移除动作的核心价值与最大风险面——库必须在没有 CurlCFFI 适配的情况下照常工作；若自动选择链或剩余客户端行为回归，所有下游用户都会受影响。

**Independent Test**: 以离线打桩测试验证单客户端环境下的自动选择与回退；真机集成冒烟验证默认选中路径的核心读与 WebSocket/下载能力。

**Acceptance Scenarios**:

1. **Given** 环境中仅安装了 aiohttp（未安装其余可选客户端），**When** 用户调用任意核心读接口，**Then** 库自动选择 aiohttp 完成请求，行为与移除前一致。
2. **Given** 环境中仅安装了 httpx，**When** 用户调用任意核心读接口，**Then** 库自动选择 httpx 完成请求，行为与移除前一致。
3. **Given** 环境中同时安装了 aiohttp 与 httpx，**When** 用户未显式选择客户端，**Then** 库按剩余优先级链选择 aiohttp（优先于 httpx）。
4. **Given** 用户此前依赖自动选择并已安装 CurlCFFI 与 aiohttp，**When** 升级到移除后的版本且未改任何代码，**Then** 库改用 aiohttp，请求正常完成，无需用户干预。

---

### User Story 2 - 曾显式使用 CurlCFFI 的用户获得清晰迁移指引 (Priority: P2)

一个此前显式使用 CurlCFFI 客户端适配的下游用户，在升级后能快速定位问题并完成迁移：以按名称选择方式使用的，首次运行得到明确异常——列出当前已注册的客户端（含剩余内置客户端）并给出自定义注册提示，"已不再内置适配"的语义由文档与变更记录承载；以直接导入适配类方式使用的，导入以标准导入错误失败（干净移除，无报错桩），迁移指引同样由文档与变更记录承载。用户据此能在短时间内完成迁移（改为使用其余内置客户端，或通过自定义客户端机制自行接入）。

**Why this priority**: 保护存量用户的升级体验，避免移除动作产生"莫名其妙不能用"的支持成本；优先级低于"库本身照常工作"，因为受影响用户面小于全体用户。

**Independent Test**: 在剩余客户端可用的环境中，分别以"按名称选择已移除客户端"与"从客户端模块导入已移除适配类"两种方式触发失败，核对按名称选择路径的异常信息指明替代方案、导入路径为标准导入错误且文档与变更记录含迁移指引。

**Acceptance Scenarios**:

1. **Given** 用户代码此前调用选择机制按名称选择了 CurlCFFI 客户端，**When** 在移除后的版本上运行，**Then** 得到明确异常，信息中列出当前已注册的客户端（含剩余内置客户端）并给出自定义注册提示。
2. **Given** 用户代码此前直接导入 CurlCFFI 适配类，**When** 在移除后的版本上运行，**Then** 导入以标准导入错误失败（适配类与模块已一并删除，无报错桩），且文档与变更记录中的迁移指引说明替代方式。
3. **Given** 用户通过自定义客户端机制注册名为已移除客户端名称的自有实现，**When** 运行并选择该名称，**Then** 该自定义实现正常生效，库不以"名称已废弃"为由拒绝。

---

### User Story 3 - 维护者获得一处不留残留的一致性收尾 (Priority: P3)

维护者完成移除后，依赖声明、测试套件、面向用户的文档与项目治理文本与库的实际行为完全一致：依赖清单不再声明 CurlCFFI；针对该适配的测试用例移除、剩余客户端的既有行为测试保留；文档中不再出现将其描述为可用选项的内容；项目治理文本中关于客户端优先级的描述同步更新。全量质量门禁与文档生成校验保持全绿。

**Why this priority**: 不影响运行时正确性，但残留引用会持续误导用户与后续维护，属于收尾必做项；因此排在两个运行时故事之后。

**Independent Test**: 全库检索（排除历史变更记录与既往规格归档）确认无将该客户端描述为可用选项的有效引用；运行质量门禁与离线测试验证一致性。

**Acceptance Scenarios**:

1. **Given** 移除完成，**When** 对代码、依赖清单与文档做全库检索（排除历史 CHANGELOG 与 specs 归档），**Then** 不存在将 CurlCFFI 描述为可用客户端的表述；确需提及处均为"已移除/历史"语境。
2. **Given** 移除完成，**When** 运行项目全量质量门禁（风格、类型、文档生成漂移校验）与离线测试，**Then** 全绿通过，无因本次移除引入的新失败。

### Edge Cases

- 用户环境**仅安装了 CurlCFFI**（未安装其余任何客户端）：移除后库无可用内置客户端，走既有的"尚未安装第三方请求库"错误路径；提示文本中列出的候选仅含剩余客户端。
- 用户已安装 CurlCFFI 但不使用：库 MUST NOT 因该库存在而产生任何加载、探测或告警行为，静默忽略。
- 用户显式注册的自定义客户端名称与已移除客户端同名：自定义注册与选择机制不受移除影响，正常生效。
- WebSocket 连接与文件下载路径：二者均经由统一客户端抽象层，移除后仅以剩余客户端运行，不得出现仅影响非 HTTP 能力的回归。
- 从旧版本升级且依赖"自动选中 CurlCFFI"的部署：升级后自动改用剩余优先级链中的客户端，属于发布说明中明示的行为变化而非缺陷。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 库 MUST 移除 CurlCFFI 的内置客户端适配实现及其在自动选择链中的登记；自动选择链 MUST 变为仅含其余客户端并保持 aiohttp 优先于 httpx 的相对顺序。
- **FR-002**: 移除后，未显式选择客户端时库 MUST 沿用既有自动选择机制在剩余客户端中选择首个可用项；既有选择、设置与连接复用机制的行为语义 MUST 保持不变。
- **FR-003**: 用户以按名称选择的方式指定已移除的内置客户端时，库 MUST 抛出项目自定义参数异常，错误信息 MUST 列出当前已注册的客户端（含剩余内置客户端，按确定性的固定顺序呈现）并给出自定义注册提示；"该客户端已不再内置适配"的语义由文档与变更记录承载（机制层报错不点名具体客户端，与"干净移除"裁决一致）。
- **FR-004**: 库的运行时与开发依赖声明 MUST 不再包含 CurlCFFI；库 MUST 在仅安装剩余客户端之一的环境下可正常初始化与工作。
- **FR-005**: 用户自定义客户端的注册、选择、注销机制 MUST 保持不变，包括注册与已移除客户端同名的实现。
- **FR-006**: 面向用户的文档（安装/配置说明、请求客户端说明、示例、README、故障排查模板）与项目治理文本（AGENTS、宪章中关于客户端优先级的描述）MUST 与新行为一致：不再将 CurlCFFI 描述为可用选项，且在恰当位置给出迁移说明；历史变更记录与既往规格归档除外。
- **FR-007**: 测试套件 MUST 移除针对 CurlCFFI 适配的用例与条件分支，保留其余客户端的超时语义、连接复用、WebSocket 等既有行为测试；离线用例 MUST 覆盖三个场景：自动回退到剩余客户端、按名称选择已移除客户端时报 FR-003 所述错误、直接导入已移除适配类时以标准导入错误失败（无报错桩）。
- **FR-008**: 本次移除属于破坏性变更，MUST 按项目规范在提交信息中以 BREAKING CHANGE 标注，并在变更记录中说明影响面与迁移方式（改用其余内置客户端，或经自定义客户端机制自行接入）。
- **FR-009**: 所有"客户端不可用"类的错误提示文本 MUST 同步更新为仅列出剩余内置客户端，不得残留对已移除客户端的安装指引。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 仅安装 aiohttp、仅安装 httpx 两种最小环境下的选择与回退能力由离线打桩测试验证全部通过；真机核心读冒烟在默认选中路径（多客户端并存取首个可用）上全部通过，等同于移除前的通过集合、无新增失败；凭据环境另提供可选的最小环境只读冒烟步骤。
- **SC-002**: 在多客户端并存环境中，自动选择结果为剩余优先级链的首个可用项，核心冒烟用例与只读集成子集全部通过。
- **SC-003**: 全库检索（代码、依赖清单、文档、测试；排除历史 CHANGELOG 与 specs 归档）中，将 CurlCFFI 描述为可用客户端的有效引用为 0 处。
- **SC-004**: 项目全量质量门禁（风格检查、格式检查、类型检查零容忍、文档生成漂移校验）与离线测试套件全绿。
- **SC-005**: 曾显式使用 CurlCFFI 的用户，依据报错信息或迁移文档可在 5 分钟内完成到其余内置客户端的切换（定性验收：报错信息含替代方案 + 文档含迁移说明）。

## Assumptions

- **移除节奏**（2026-10-11 澄清确认）：立即彻底移除，不设废弃过渡期；破坏性影响通过 BREAKING CHANGE 标注与变更记录告知。
- **移除动机**（用于价值主张，不改变范围）：降低二进制依赖带来的安装失败与平台兼容负担，缩减适配面与升级跟进成本。
- **范围边界**：仅移除内置适配；不禁止也不妨碍用户通过既有自定义客户端机制注册任何同名第三方实现。
- **版本语义**：版本号如何递增（major 与否）由发布流程决定，本规格不约束。
- **历史文本**：既往 CHANGELOG 与 specs 归档中的提及属于历史事实记录，一律不回改。
- **治理文本**：宪章中关于客户端优先级的描述属于事实漂移，按宪章修订程序以独立提交修订，随本特性一并处理。
